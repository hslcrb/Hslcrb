# 프로필 저장소 개발기

> 가능성을 구현하는 Creator — 그 기록의 기록.

## 기록 원칙

- 파일 이름은 YYYY-MM-DD-주제.md 형식을 사용하고, 날짜는 한국 표준시를 기준으로 한다.
- 실제 작업의 목적, 변경 전 상태, 대안, 선택 근거, 적용 과정, 변경 커밋, 확인 결과 및 남은 문제를 기록한다.
- 도식은 Mermaid로 작성하고, 구조 설명과 실제 관측 결과를 구분한다.
- CLI 명령은 실행 여부와 검증 결과를 구분한다.
- 소급 기록에는 소급 작성 사실과 근거를 명시한다.
- 비공개 정보, 인증 정보, 내부 자격 증명은 기록하지 않는다.
- 커밋 메시지는 변경의 성격과 범위를 드러내도록 작성한다. 예: docs(devlog): record profile maintenance.

## 개발기 기본 구조

1. 배경과 목적
2. 변경 전 구조
3. 조사 및 시행착오
4. 해결 방향과 선택 이유
5. 실제 변경 및 커밋
6. 검증 결과와 미검증 범위
7. 재현 명령 및 남은 과제

기록을 남기기 위한 변경이 실제 기능 개선을 대신하지 않도록 한다. 자동화 없이 직접 기록할 수 있으며, 향후 기록은 필요한 변경에 맞추어 추가한다.
